# 新增中台功能模块说明

## 一、建设目标

本次新增的 4 个中台功能模块，主要用于补齐计划协同、品质封样、订单执行标准、现场作业标准这几类关键业务资料的线上化管理能力。

新增模块包括：

- 计划排产
- 产品封样
- 订单标准
- 作业指导书

整体目标是把原来分散在 Excel、群消息、纸质文件、个人电脑中的计划和标准资料，统一沉淀到系统中，形成可查询、可追溯、可授权、可版本管理的业务台账。

## 二、模块总览

| 模块 | 所属中心 | 主要用途 | 主要使用部门 |
| --- | --- | --- | --- |
| 计划排产 | 生产协同中心 | 记录各部门计划安排、排期、负责人、状态和优先级 | 计划、采购、生产、品质、仓储 |
| 产品封样 | 异常与质量中心 | 管理产品封样资料、样品确认依据和历史版本 | 品质、工程、生产、业务 |
| 订单标准 | 规则配置中心 | 管理订单执行标准、客户要求、交付规则和特殊要求 | 业务、计划、生产、品质 |
| 作业指导书 | 规则配置中心 | 管理工序作业方法、操作要求、注意事项和附件资料 | 工程、生产、品质 |

## 三、计划排产

### 1. 模块用途

计划排产用于管理不同部门围绕订单和生产任务形成的计划安排。系统按部门拆分标签页，默认包括：

- 计划
- 采购
- 生产
- 品质
- 仓储

每个部门只维护和查看自己部门维度的计划数据，也可以通过权限控制开放跨部门查看。

### 2. 解决的问题

计划排产模块主要解决以下问题：

- 各部门计划分散在不同 Excel 中，无法统一查看。
- 订单计划、采购计划、生产计划、品质检验计划、仓储出入库计划之间缺少联动。
- 计划调整后无法追踪负责人、状态和日期变化。
- 管理者无法快速判断哪些任务延期、哪些任务优先级高。
- 跨部门会议时需要临时汇总计划，效率低。

### 3. 主要数据

计划排产台账记录以下信息：

- 部门
- 计划日期
- 订单号
- 产品或型号
- 数量
- 负责人
- 开始日期
- 结束日期
- 优先级
- 状态
- 备注

### 4. 使用场景

典型使用场景包括：

- 计划部门登记订单排产计划。
- 采购部门登记关键物料到料计划。
- 生产部门登记生产开工、完工计划。
- 品质部门登记检验、封样、首件确认计划。
- 仓储部门登记备料、入库、出货计划。
- 管理者按订单号或产品查询跨部门计划进度。

### 5. 业务价值

上线后可以实现：

- 各部门计划统一入口管理。
- 按部门、状态、日期、关键字快速筛选。
- 计划任务责任人清晰。
- 重要计划可设置优先级。
- 计划状态可持续跟踪，减少口头同步和重复确认。

## 四、产品封样

### 1. 模块用途

产品封样用于管理产品样品确认相关资料，包括封样说明、适用产品、附件、图片、确认内容和历史版本。

产品封样资料属于品质类基础依据，通常用于生产、检验、客户确认和异常判定。

### 2. 解决的问题

产品封样模块主要解决以下问题：

- 封样资料存放分散，现场查找困难。
- 样品版本不清楚，容易使用旧版资料。
- 产品外观、关键尺寸、特殊要求缺少统一记录。
- 品质判定时缺少可追溯依据。
- 封样变更后旧记录无法保留。

### 3. 主要数据

产品封样资料记录以下信息：

- 编码
- 标题
- 适用产品
- 当前版本
- 状态
- 正文内容
- 附件列表
- 生效日期
- 发布人
- 发布时间

### 4. 使用场景

典型使用场景包括：

- 品质人员创建产品封样资料。
- 上传封样图片、客户确认资料、检验标准附件。
- 发布 V1.0 封样版本。
- 产品要求变化后发布 V1.1 或 V2.0 新版本。
- 生产和品质人员按产品查询当前有效封样资料。
- 出现争议或异常时查看历史封样版本。

### 5. 业务价值

上线后可以实现：

- 封样资料集中管理。
- 当前版本和历史版本清晰。
- 品质判定有据可查。
- 防止现场误用过期资料。
- 支持附件沉淀，方便查看图片、文件和确认记录。

## 五、订单标准

### 1. 模块用途

订单标准用于管理订单执行过程中的标准要求，包括客户要求、订单类型要求、交付要求、包装要求、检验要求、特殊备注等。

它是订单交付过程中的规则依据，帮助不同岗位按统一标准执行订单。

### 2. 解决的问题

订单标准模块主要解决以下问题：

- 客户或订单特殊要求分散在订单备注、聊天记录或人工经验中。
- 同类订单执行标准不统一。
- 新员工或跨部门人员不清楚订单要求。
- 订单变更后标准缺少版本记录。
- 出现交付问题时难以追溯当时执行的是哪版标准。

### 3. 主要数据

订单标准资料记录以下信息：

- 编码
- 标题
- 适用订单
- 适用产品
- 当前版本
- 状态
- 正文内容
- 附件列表
- 生效日期
- 发布人
- 发布时间

### 4. 使用场景

典型使用场景包括：

- 业务或计划人员维护客户订单执行标准。
- 生产、品质、仓储根据订单标准执行对应要求。
- 管理特殊客户的包装、标签、交付、检验要求。
- 订单标准调整后发布新版本，保留旧版本记录。
- 出现客诉、交付异常时追溯订单执行依据。

### 5. 业务价值

上线后可以实现：

- 订单要求标准化。
- 特殊客户和特殊订单要求不再依赖个人记忆。
- 订单执行标准可查询、可追溯。
- 跨部门按同一套标准执行，减少理解偏差。
- 支持后续与订单详情页、风险预警、规则引擎联动。

## 六、作业指导书

### 1. 模块用途

作业指导书用于管理现场工序操作文件，包括操作步骤、工艺要求、注意事项、检验点、设备要求、安全要求和附件资料。

它是生产现场标准作业的重要依据。

### 2. 解决的问题

作业指导书模块主要解决以下问题：

- 作业文件以纸质或本地文件形式存在，不便统一维护。
- 现场使用的指导书版本不一致。
- 工序变更后旧版资料没有留痕。
- 新员工培训缺少标准化资料。
- 品质异常时难以判断现场是否按正确版本执行。

### 3. 主要数据

作业指导书资料记录以下信息：

- 编码
- 标题
- 适用工序
- 适用产品
- 当前版本
- 状态
- 正文内容
- 附件列表
- 生效日期
- 发布人
- 发布时间

### 4. 使用场景

典型使用场景包括：

- 工程人员创建或维护作业指导书。
- 上传 SOP、工艺图、设备参数、检验示意图等附件。
- 生产人员按工序查询当前有效指导书。
- 品质人员根据指导书检查作业是否符合要求。
- 工艺变更后发布新版本，保留历史版本。

### 5. 业务价值

上线后可以实现：

- 作业标准统一维护。
- 现场执行依据清晰。
- 新员工培训资料可沉淀。
- 工艺变更可追溯。
- 生产异常、品质异常分析时能回看当时有效指导书。

## 七、资料版本管理机制

产品封样、订单标准、作业指导书都属于资料类模块，共用版本管理机制。

### 1. 状态说明

资料主档支持以下状态：

- 草稿：资料正在编辑，尚未正式生效。
- 已发布：资料已发布，可作为业务执行依据。
- 已归档：资料不再使用，但历史记录保留。

### 2. 版本规则

每次发布或修订资料时，系统会生成一条新的版本记录，并更新主档当前版本。

旧版本不会被覆盖，仍可查看历史内容、附件、生效日期、发布人和发布时间。

### 3. 业务意义

版本管理的意义在于：

- 避免资料被直接覆盖，导致历史依据丢失。
- 能追溯某个时间点使用的是哪个版本。
- 支持资料修订、发布、生效的全过程留痕。
- 方便后续扩展审批流、电子签核、变更通知。

## 八、权限说明

新增权限点如下：

| 权限点 | 对应模块 |
| --- | --- |
| production.schedule_plans | 计划排产 |
| exceptions.product_samples | 产品封样 |
| rules.order_standards | 订单标准 |
| rules.work_instructions | 作业指导书 |

每个权限点支持：

- 新增
- 查看
- 编辑
- 删除

资料类模块的“发布新版本”走编辑权限。

## 十、上线后的使用建议

建议上线后按以下步骤推进：

1. 先由管理员在用户管理中给相关角色分配新增权限。
2. 由计划、品质、工程、业务分别整理现有 Excel 和纸质资料。
3. 将常用资料先录入系统，发布第一个正式版本。
4. 现场人员开始按系统资料查询和执行。
5. 后续资料变更统一通过“发布新版本”完成，不再直接覆盖旧资料。
6. 定期检查已归档资料和过期资料，保持资料库整洁。

## 十一、后续可扩展方向

当前版本先实现台账、附件和版本追溯。后续可以继续扩展：

- 资料审批流
- 发布通知
- 电子签核
- 与订单详情页联动
- 与生产工序页面联动
- 与品质异常分析联动
- 资料到期提醒
- 动态部门配置
- 按产品、客户、订单自动匹配标准资料
