> 目标：把 80/443 从恒聘通 nginx 中拆出来，独立 `docker compose` 部署一个边缘 Nginx；每个应用绑定独立子域名，按域名转发到各自端口。

## 1. 结论摘要

- 新增独立边缘容器 `edge-nginx`，独占宿主机 80/443，统一终止 TLS。
- 采用 **host 网络 + 回环端口**：边缘 Nginx 直接访问 `127.0.0.1:<应用端口>`，应用只监听回环端口，不再各自绑定 80/443。
- 恒聘通 nginx 退到 `127.0.0.1:18088`，只服务 `hengpintong.com` / `www.hengpintong.com`，继续负责它自己的静态资源、`/api`、`/uploads`、限流和安全头。
- 每个应用一个 vhost 文件，互不覆盖；恒聘通发版不再影响 SPC 或其他域名。
- 证书统一迁到 `edge-nginx/certs`，续期统一走一个新的 Let's Encrypt 目录 + 一个 cron 脚本，不再依赖恒聘通容器名和发版目录。
- **必须同步修改恒聘通 nginx 的真实 IP / `X-Forwarded-Proto` 处理**：否则边缘反代后，恒聘通的登录限流会把所有用户当成 `127.0.0.1`，并且后端会认为请求是 HTTP。
- 迁移窗口约 15–30 分钟，回滚约 2 分钟。
- 核心 Nginx 配置已用 `nginx:1.27-alpine` 做过 `nginx -t` 语法校验（含 `ssl_reject_handshake`、`http2 on`、`real_ip`、`limit_req`）。

## 3. 目标架构

```text
                       Internet
                          │ 80 / 443
                          ▼
        ┌─────────────────────────────────────┐
        │ edge-nginx (docker compose, host)   │
        │ TLS 终止 / 域名路由 / ACME / 日志    │
        └─────────────────────────────────────┘
             │            │            │
             │            │            └──► 127.0.0.1:18080  PLM
             │            └───────────────► 127.0.0.1:18088  恒聘通 nginx ──► backend
             └────────────────────────────► 127.0.0.1:18084  SPC 前端 ──► SPC backend
                          ├──► 127.0.0.1:18091  meeting
                          ├──► 127.0.0.1:18092  恒鉴 AI
                          └──► 127.0.0.1:4174   M10 POMS
```

### 3.1 设计原则

1. **公网入口只有一个**：边缘 Nginx 独占 80/443，其它应用不再绑定公网 80/443。
2. **TLS 只在边缘终止**：应用侧 nginx 只处理 HTTP，不再持有公网证书。
3. **一个域名一个配置文件**：恒聘通发版只覆盖它自己的文件，不会影响 SPC。
4. **默认站点拒绝未知域名**：`server_name _` 返回 444 / 拒绝 TLS 握手，避免“配置丢了就落到恒聘通”。
5. **端口全部回环**：`127.0.0.1:<port>`，不暴露公网；边缘使用 host 网络直接访问。
6. **客户端真实 IP 不丢**：边缘覆盖写 `X-Forwarded-For`，应用 nginx 信任 `127.0.0.1` 并用 `real_ip` 还原。
7. **配置可校验、可回滚**：改配置先 `nginx -t`，保留旧配置和旧端口，回滚 2 分钟。

### 3.2 为什么用 host 网络

| 方案 | 优点 | 缺点 |
|---|---|---|
| **host 网络 + 回环端口（推荐）** | 边缘直接访问 `127.0.0.1:port`；应用端口可只绑回环；不依赖 Docker 网络名；改动最小 | 容器共享宿主网络命名空间；需要 root 绑 80/443 |
| bridge + `host.docker.internal` | 容器网络隔离 | 应用若绑 `127.0.0.1`，bridge 容器访问不到；需绑 `0.0.0.0` 或改网络，反而更复杂 |
| 共享 Docker external network | 纯 Docker 原生，无宿主端口 | 每个应用都要改 compose 加入同一网络；恒聘通网络名变化会连带影响 |

本机应用多、归属团队多、已有大量 `172.18.0.1:<port>` 反代，host 网络 + 回环端口是改动面最小、最容易回滚的方案。

```yaml
    restart: unless-stopped
    network_mode: host
    read_only: true
    tmpfs:
      - /var/cache/nginx:size=64m,mode=0755
      - /run:size=8m,mode=0755
      - /tmp:size=16m,mode=1777
    volumes:
      - ./conf.d:/etc/nginx/conf.d:ro
      - ./snippets:/etc/nginx/snippets:ro
      - ./certs:/etc/nginx/certs:ro
      - ./www:/var/www:ro
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1/healthz >/dev/null 2>&1"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "5"
```

说明：

- `network_mode: host` 下不要再写 `ports`；Nginx 直接监听宿主机 80/443。

- 官方镜像的 entrypoint 可能尝试改 `/etc/nginx/conf.d/default.conf`，只读时会打印 warning，不影响启动。

## 6. Nginx 配置

### 6.1 `conf.d/00-main.conf`

```nginx
server_tokens off;

log_format edge '$remote_addr - $host [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" "$http_user_agent" '
                'upstream=$upstream_addr rt=$request_time urt=$upstream_response_time';
access_log /dev/stdout edge;

map $http_upgrade $connection_upgrade {
    default upgrade;
    ""      close;
}

ssl_protocols TLSv1.2 TLSv1.3;
ssl_prefer_server_ciphers off;
ssl_session_cache shared:SSL:10m;
ssl_session_timeout 1d;
ssl_session_tickets off;
```

### 6.2 `conf.d/00-default.conf`

```nginx
# 未知域名一律拒绝，避免配置缺失时落到某个应用
server {
    listen 80 default_server;
    return 444;
}

# 未知 SNI 直接拒绝 TLS 握手，不返回错误证书
server {
    listen 443 ssl default_server;
    ssl_reject_handshake on;
}

# 边缘自身健康检查
server {
    listen 80;
    server_name localhost 127.0.0.1;
    location = /healthz {
        access_log off;
        return 200 "ok\n";
    }
    location / { return 444; }
}
```

> ```nginx

> }
> ```

```nginx
    listen 443 ssl;

    ssl_certificate_key /etc/nginx/certs/hengpintong.com.privkey.pem;
```

## 7. 客户端真实 IP 与 `X-Forwarded-Proto`（必须处理）

边缘反代后，应用 nginx 看到的 `$remote_addr` 会变成 `127.0.0.1`。这会带来两个真实问题：

1. **恒聘通登录限流失效/误伤**：`limit_req_zone $binary_remote_addr zone=login_zone rate=5r/m;` 会把所有用户当成同一个 IP，几个人登录就互相 429。
2. **恒聘通后端认为请求是 HTTP**：它当前用 `X-Forwarded-Proto $scheme`，边缘终止 TLS 后 `$scheme` 变成 `http`，可能导致 secure cookie、回调地址、绝对 URL 错误。

### 7.1 恒聘通 nginx 补丁（切割前先打，可独立验证）

在 `/home/ubuntu/apps/hrm-saas/shared/nginx-docker.conf` 顶部（http 上下文）加：

```nginx
# edge-nginx 在 127.0.0.1 终止 TLS，恢复真实客户端 IP 与原始协议
set_real_ip_from 127.0.0.1;
real_ip_header X-Forwarded-For;
real_ip_recursive on;

map $http_x_forwarded_proto $forwarded_proto {
    default $http_x_forwarded_proto;
    ""      $scheme;
}
```

然后把该文件中所有：

```nginx
proxy_set_header X-Forwarded-Proto $scheme;
```

替换为：

```nginx
proxy_set_header X-Forwarded-Proto $forwarded_proto;
```

验证：

- 直接访问 `http://127.0.0.1:80/`（未切割时）行为不变；没有 `X-Forwarded-Proto` 头时 `$forwarded_proto` 回退到 `$scheme`。
- 带 `X-Forwarded-For: 1.2.3.4` 访问登录接口，限流应按 1.2.3.4 计数，而不是 127.0.0.1。

### 7.2 SPC 前端 nginx 补丁

在 `scripts/remote/nginx.conf` 的 `server` 块加：

```nginx
set_real_ip_from 127.0.0.1;
real_ip_header X-Forwarded-For;
real_ip_recursive on;
```

这样 `proxy_set_header X-Real-IP $remote_addr;` 传给后端的是真实客户端 IP。

建议同时在文件顶部（http 上下文，`resolver` 附近）加：

```nginx
map $http_x_forwarded_proto $forwarded_proto {
    default $http_x_forwarded_proto;
    ""      $scheme;
}
```

并在 `/api/`、`/uploads/` 的反代 location 里补：

```nginx
proxy_set_header X-Forwarded-Proto $forwarded_proto;
```

这样 SPC 后端在 HTTPS 下能正确识别原始协议（secure cookie、回调地址、绝对 URL）。

### 7.3 PLM / 其它应用

- PLM 前端如果有基于 IP 的限流或日志，建议同样加 `real_ip` 配置。
- meeting / AI / POMS 是应用直接接收边缘请求，边缘已经传 `X-Forwarded-For`，应用侧按自己的 `trust proxy` 配置读取即可。

### 8.3 统一续期脚本

`/usr/local/sbin/renew-edge-certs`：

```bash
#!/bin/bash
set -euo pipefail

EDGE=/home/ubuntu/apps/edge-nginx
LE="$EDGE/letsencrypt"
WEBROOT="$EDGE/www/acme"
EMAIL="${CERTBOT_EMAIL:?set CERTBOT_EMAIL}"
LOG=/var/log/renew-edge-certs.log

# cert-name|额外的 -d 域名（逗号分隔）
CERTS=(
  "hengpintong.com|hengpintong.com,www.hengpintong.com"
  "ai.hengpintong.com|ai.hengpintong.com"
  "meeting.hengyou-soft.com|meeting.hengyou-soft.com"
  "spc.hengyou-soft.com|spc.hengyou-soft.com"
  "wxt.hengyou-soft.com|wxt.hengyou-soft.com"
  "plm.hengpintong.com|plm.hengpintong.com"
  "poms.hengpintong.com|poms.hengpintong.com"
)

run_certbot() {
  docker run --rm \
    -v "$LE:/etc/letsencrypt" \
    -v "$WEBROOT:/var/www/acme" \
    certbot/certbot:latest "$@"
}

# 首次签发（已存在同名 lineage 则跳过）
for entry in "${CERTS[@]}"; do
  name="${entry%%|*}"
  domains="${entry#*|}"
  [ -d "$LE/live/$name" ] && continue
  args=()
  IFS=',' read -ra names <<< "$domains"
  for d in "${names[@]}"; do args+=(-d "$d"); done
  run_certbot certonly --webroot -w /var/www/acme \
    --cert-name "$name" "${args[@]}" \
    --email "$EMAIL" --agree-tos --non-interactive \
    || { echo "WARN: issue $name failed, keep existing cert"; continue; }
done

# 续期（单个失败不阻断其它证书）
run_certbot renew --webroot -w /var/www/acme --non-interactive \
  || echo "WARN: certbot renew reported failures"

# 同步到边缘证书目录
for entry in "${CERTS[@]}"; do
  name="${entry%%|*}"
  src="$LE/live/$name"
  [ -f "$src/fullchain.pem" ] || continue
  cp -L "$src/fullchain.pem" "$EDGE/certs/$name.fullchain.pem"
  cp -L "$src/privkey.pem"   "$EDGE/certs/$name.privkey.pem"
  chmod 644 "$EDGE/certs/$name.fullchain.pem"
  chmod 600 "$EDGE/certs/$name.privkey.pem"
done

docker exec edge-nginx nginx -t
docker exec edge-nginx nginx -s reload
echo "$(date) edge certs renewed & nginx reloaded"
```

cron：

```cron
30 3 * * * CERTBOT_EMAIL=ops@example.com /usr/local/sbin/renew-edge-certs >> /var/log/renew-edge-certs.log 2>&1
```

续期链路验证（切割后执行）：

```bash

  -v /home/ubuntu/apps/edge-nginx/letsencrypt:/etc/letsencrypt \
  -v /home/ubuntu/apps/edge-nginx/www/acme:/var/www/acme \

```

同时**停用**旧的三个脚本（`renew-ai-hengpintong-cert`、`renew-meeting-cert`、`renew-spc-cert`），避免它们继续往旧目录写并 reload 旧的恒聘通容器。

## 14. 风险与后续

| 风险 | 影响 | 缓解 |
|---|---|---|
| 恒聘通发版覆盖 `shared/.env` | 端口被改回 80/443，边缘无法启动 | 已确认正常发版使用 `--env-file shared/.env` 且不覆盖；和团队书面确认，发版后检查 `docker port` |
| 恒聘通 real_ip/XFP 补丁遗漏 | 登录限流误伤、secure cookie 异常 | 切割前先打补丁并在 80/443 现网验证 |
| 证书续期未切换 | spc/meeting 12 月到期后 HTTPS 失败 | 切割当天启用 `renew-edge-certs`，11 月中旬前完成 dry-run |
| 边缘单点 | 边缘挂掉所有域名不可用 | `restart: unless-stopped` + 健康检查 + 外部监控；后续可考虑双实例/keepalived |
| 端口仍绑 0.0.0.0 | 绕过边缘直接访问应用 | 第二阶段把 18084/18080/4174 等改为 `127.0.0.1:`；安全组只放行 80/443 |
| `read_only` 导致启动失败 | 边缘起不来 | 首次上线先不加 `read_only`，稳定后再加 |
| HSTS 范围扩大 | 子域名 HTTP 被浏览器强制 HTTPS | 先不加 `includeSubDomains`，确认所有子域名 HTTPS 后再加 |

### 后续加固建议

1. **收口高位端口**：安全组只放行 80/443/SSH；应用端口改绑 `127.0.0.1`。
2. **数据库/Redis/MinIO 不对公网暴露**：当前 `15432`、`16379`、`19000/19001` 绑 `0.0.0.0`，建议改内网/VPN 或安全组白名单。
3. **解决 18086 冲突**：`ztrz-ems` 已占用 18086，SPC 的 `aeos-gateway` 启动会失败；改成 18089/18090 并同步调用方。
4. **边缘配置纳入 Git**：每次改配置走 `nginx -t` + reload，保留变更记录。
5. **监控证书到期**：到期前 21 天告警，避免再次出现“续期脚本依赖别人容器名”的问题。
