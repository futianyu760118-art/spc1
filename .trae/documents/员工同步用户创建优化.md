# 员工同步用户创建优化计划

## 需求
优化员工同步逻辑，实现：如果系统用户中已经存在与该员工匹配的账号（包括通过 `emp_code` 关联的，或通过 `username` 匹配的），就不需要再创建新用户。

## 当前状态分析

### 数据模型关系
1. **Employee 模型**：
   - `emp_code`: 员工工号（唯一）
   - `login_id`: 登录ID
   - `oa_user_id`: OA系统用户ID

2. **SysUser 模型**：
   - `username`: 用户名（唯一）
   - `emp_code`: 关联的员工工号（可以为空）
   - `is_active`: 是否激活

### 当前逻辑（erp_sync_service.py 第1478-1531行）
1. 通过 `emp_code` 查询是否已存在关联的系统用户（第1480行）
2. 如果存在，更新用户信息（第1484-1512行）
3. 如果不存在，创建新用户，并在创建前检查 username 是否冲突（第1517-1520行）

### 问题
当前实现主要通过 `emp_code` 判断用户是否存在，但可能存在以下情况：
- 如果员工已经有用户名（login_id），但该用户名对应了另一个 `emp_code` 的用户记录，就会尝试创建新用户
- 这可能导致多个员工共享同一个 username（如果先前的创建因 username 冲突被跳过）

## 改进方案

### 核心改进
在创建新用户前，增加 username 匹配检查：
1. **核心对应关系**：Employee.login_id ↔ SysUser.username
2. **查询逻辑**：通过 `Employee.login_id` 查询 `SysUser.username`，如果存在匹配则不创建
3. **跳过创建**：如果通过 login_id 能找到对应的 username，就跳过创建步骤
4. **添加统计**：在 stats 中添加 `users_skipped` 统计已跳过的用户数

### 具体修改

#### 文件：backend/app/services/basicdata/erp_sync_service.py

**位置**：第1513-1531行（创建新用户的部分）

**修改内容**：
```python
# 创建新的系统用户
username = emp.login_id or emp.emp_code

# 检查 username 是否已存在（通过 Employee.login_id 查询 SysUser.username）
username_check = await self.spc_db.execute(
    select(SysUser).where(SysUser.username == username)
)
existing_by_username = username_check.scalar_one_or_none()

if existing_by_username:
    # 如果 username 已存在（通过 login_id 匹配），跳过创建
    stats["users_skipped"] = stats.get("users_skipped", 0) + 1
    logger.info(f"跳过创建系统用户: {username} (员工: {emp.emp_name}) - 用户名已存在")
else:
    # 创建新用户
    new_user = SysUser(
        username=username,
        display_name=emp.emp_name,
        hashed_password=get_password_hash("admin123"),
        role_id=default_role_id,
        emp_code=emp.emp_code,
        is_active=(emp.status == 1),
    )
    self.spc_db.add(new_user)
    stats["users_created"] += 1
    logger.info(f"自动创建系统用户: {username} (员工: {emp.emp_name})")
```

### 统计字段调整
- 在第1409行的 stats 中添加 `users_skipped` 字段，初始值为 0
- 在第1531行的 return stats 前确保包含 `users_skipped` 字段

## 实现步骤

1. **修改 sync_employees 函数**：
   - 在 stats 初始化时添加 `users_skipped: 0`
   - 在创建用户逻辑前添加 username 冲突检查
   - 如果 username 存在，跳过创建并记录到 `users_skipped`

2. **验证逻辑**：
   - 确保只在真正需要创建时才创建
   - 确保 username 冲突时正确跳过
   - 确保日志和统计准确

## 预期效果

- 同步员工时，如果系统用户中已经存在该员工的账号（通过 `emp_code` 或 `username` 匹配），将跳过创建步骤
- 统计信息更清晰：`users_created`（已创建）、`users_updated`（已更新）、`users_skipped`（已跳过）
- 避免重复创建和用户名冲突问题

## 假设与决策

1. **"这个员工的账号"的定义**：指 SysUser 表中 username 等于 Employee.login_id 的记录
2. **对应关系**：`Employee.login_id` = `SysUser.username`
3. **查询方式**：通过 `Employee.login_id` 查询 `SysUser.username`
4. **跳过逻辑**：如果查询到匹配的 username，跳过创建而不是报错或关联
